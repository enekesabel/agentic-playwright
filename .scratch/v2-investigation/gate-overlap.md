## 3. OLD link-gate checks with no NEW equivalent

Source: `OLD:scripts/check-skill-references-drift.sh:5-26`.

- Scope is wider: `.claude/**`, `.cursor/**`, `.github/**`, root docs, `eslint.config.mts`, `scripts/*.sh` (`:12-16`). NEW references-drift walks only `.claude/skills/*/SKILL.md` (`scripts/check-skill-references-drift.sh:13-14`, find at bottom).
- Links in non-skill files and gate-script/ESLint/hook comments (`file.md#anchor` bare tokens, `.mdc#anchor`) resolved (failure 1-2): no NEW counterpart; NEW gate scripts name rules in comments only.
- Inline `<a id>` / `<a name>` anchors accepted (`:20-21`): NEW slugify headings only (`## `).
- Path in prose (failure 4, `:24-25`): backticked path to an existing rule-tree .md must be a link. NEW is the opposite: `REF_MENTION` (`scripts/check-heading-pointers.sh:50`) expects backticks.
- Reference-style `[x]: target` definitions rejected (failure 5, `:26`): none.
- Fence/inline-code/angle-bracket handling (`:30-34`): not needed in NEW (no link syntax).
- Per-skill vendored exemption read from skills-lock.json for orphans (NEW does the same in shape/crossrefs, not in references-drift).
- Fixture self-test (see 5).
- Mirror drift: `OLD:scripts/check-mirrors.sh` (Cursor/Copilot trees); NEW has `.agents/skills` sync instead.

## 4. Cost of anchors + Markdown links against NEW caps

Current numbers (measured):

- `AGENTS.md`: 87 lines, 773 words. Caps 100 lines, 800 words (`scripts/check-agents-md.sh:45-46`). Headroom 13 lines, 27 words. 36 rows (lines 11-24, 28-32, 36-52).
- `CLAUDE.md`: 9 lines, 122 words; caps 30 / 250 (`:47-48`). Not affected.
- Largest SKILL.md: ai-native-workflow 60 lines / 596 words; pr-reviewer 54 / 597; api-testing 53 / 533; data-strategy 53 / 479. Caps 100 / 600 (`scripts/check-skill-shape.sh:44-45`). Words headroom: pr-reviewer 3, ai-native-workflow 4, debugging 589 -> 11, api-testing 67.
- Critical caps 25 lines / 250 words (`:47-48`): api-testing 21 lines / **250 words (at cap, 0 headroom)**, type-safety 21 / 238, test-standards 20 / 194, data-strategy 20 / 218, page-objects 19 / 212.
- All scaffold skills total 686 lines / 6611 words vs caps 1500 / 9000 (OK). References caps 150 lines / 1000 words; largest scaffold ref not near cap.
- Prose pointers to convert in SKILL.md: 51 `` `references/x.md` `` mentions, ~11 `step N` mentions, 0 `→ "Heading"`.

Estimate:

- Anchor `<a id="rule-slug"></a>` on all 36 rows: 0 lines if inline; words: if written `<a id="x"></a>**Name**:` glued, whitespace tokenizer adds 1 token per row (`<a` separated from `id=...`), so +36 words = 809 > 800: **AGENTS.md word cap fails (by 9)** even before any link. If a space follows `</a>` it is +2/row = +72 (845). Lines unchanged unless anchors go on their own lines (+36 = 123 > 100, fail).
- Bare `@` rule (`:~104-116`): anchors and links contain no `@`; safe. Note existing text uses code spans for `@smoke`.
- Row-key extraction breaks: `grep -oE '^- \*\*[^*]+\*\*'` (`scripts/check-rules-drift.sh:125`) needs `- **` at line start. An `<a id>` prefix makes all 36 rows "missing" unless the anchor goes after the bold name (or the regex is changed).
- Index regex `^- \`name\`` (`scripts/check-agents-md.sh:131`) would break if index entries become `[name](...)` links.
- Links replacing a name in prose keep word count (a link `[Name](x)` tokenizes like the name plus a glued path), so skill/Critical word caps are roughly neutral for pure conversions; added link text costs words. Critical blocks at risk: api-testing (0 words headroom), type-safety (12), data-strategy (32). SKILL.md total at risk: pr-reviewer (3), ai-native-workflow (4).
- Harness wording regex (`scripts/check-skill-shape.sh:59`) rejects `.claude/` and `CLAUDE.md` in any skill file text, including link targets. Links from a skill to AGENTS.md as `../../../AGENTS.md#...` are fine; a link target containing `.claude/` or `CLAUDE.md` fails. Relative depth is identical in the `.agents/skills` copy, so sync stays valid.
- Manifest tokens: replacing a Critical sentence with a link to the AGENTS.md anchor would break `scripts/check-rules-drift.sh:46-70` unless the token stays in text (e.g. `NEVER** use \`any\``in the`type-safety`Critical). Conflicts with the restatement model, same conflict`OLD:RULE-TREE-SPEC.md:13,15` retired.
- references-drift regex (`:49-55`) already matches the path inside a Markdown link target, so link conversion of `references/x.md` stays compatible; backtick-dependent `REF_MENTION` (heading-pointers `:50`) would stop seeing converted ones (only matters for `→ "Heading"` lines, none exist).
- Line caps: link conversions are in-place, so line counts unchanged; skill line caps (100) at risk only if anchors go on separate lines.

At risk: AGENTS.md word cap (27 headroom vs +36 minimum), `check-rules-drift` row regex, Skills Index regex, api-testing Critical word cap. Not at risk: line caps, bare-`@`, fences, total skill caps.
