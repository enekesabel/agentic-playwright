# Notes for upstream

Questions and decisions from rebuilding "one home per rule, links elsewhere" on top of v2.0.1. Written for the maintainer; nothing here changes a rule. Each item names the files involved so it can be checked without reading the branch.

The branch applies one rule: a Constitution rule lives only in its `AGENTS.md` row, a skill-local rule lives only in its skill's `## Critical` block, and everywhere else is a Markdown link whose text is the rule's name. A skill sentence was treated as contradicting its row only where following the sentence would violate the row. Everything the row is silent on stayed as skill-local text after the link.

Evidence: `.scratch/v2-investigation/` holds the restatement census and question triage over v2.0.1 that motivated the branch, the conversion rules, and the per-commit conversion notes.

## A. Decided on this branch, for confirmation

Each is a place where the skill or doc copy contradicted its row. The row won. If the row was wrong, the fix is one line in `AGENTS.md`.

1. **Imports and No Manual Instantiation lost their scope in v2.** `AGENTS.md` said "never `@playwright/test`" and "never `new PageObject(page)`" with no scope, while `page-objects` requires the `@playwright/test` import and `fixtures` requires `new X(page)` in fixture registration. The pre-v2 rows said "in spec files" and "inside test files"; restored (commit "fix(rules): restore the scope qualifiers v2 dropped").
2. **API fallback when no OpenAPI document exists.** The row allows a flagged live capture; `api-testing` Critical and `references/contract-sourcing.md` said "stop and ask" while the same reference explained how to capture. The skill now matches the row.
3. **App unreachable while capturing a UI message.** `enums/SKILL.md` said "add it with `// FIXME: unverified` and say so in the report"; the Explore Before Generate row says "cannot run means stop and tell the human", and `ai-native-workflow` forbids unverified message strings. The sentence is removed; the row is linked.
4. **`config/` as a source of URLs.** `pr-reviewer/references/constitution-checklist.md` and `.github/prompts/pr-reviewer.prompt.md` listed `enums/*` / `config/*`; the Sources of Truth row names `process.env.*` and `enums/` only. Now linked to the row.
5. **README softer than the Constitution.** `README.md` listed `page.locator()` CSS/XPath as a last-resort tier and said "Avoid `any`"; the rows say No XPath and No `any`. Both now link the row and keep the surrounding explanation.
6. **The selectors exception in the review checklist.** The checklist restated the labelled-field exception (`getByLabel` over `getByRole('textbox')`). It now links the Selectors row; the exception lives once, in `selectors` Critical, as skill-local detail.

## B. Open questions the branch did not decide

Skill-local sentences that passed the test (following them does not violate a row) but look like they want a decision.

7. **Type Safety row has no skill that teaches it.** `AGENTS.md` "Type Safety: Zod schemas in `fixtures/api/schemas/`; no `any`" is covered by Strict Schemas and No `any`; after conversion no Critical block links it. The new `check-rules-drift.sh` allowlists it with a reason. Is the row a duplicate to drop, or should `type-safety` Critical link it?
8. **Test Steps row is linked from Procedures only.** `test-standards` step 4 and `api-testing` apply Given/When/Then, but no Critical block links the SHOULD row. Allowlisted the same way. Acceptable, or should one Critical block own it?
9. **JSDoc on Actions is a SHOULD, two skills say "required".** `page-objects/SKILL.md` Critical: "JSDoc with `@param` and `@returns` is required on every action and verification method" (and the row says actions only). `helpers/SKILL.md` requires JSDoc on every exported helper; `enums/SKILL.md` on every enum declaration. Kept verbatim after the link. Are these skill-level MUSTs on purpose?
10. **Enums for Strings is a SHOULD, `enums` says "lives in an enum".** `enums/SKILL.md` Critical: any app-defined string used in more than one place lives in an enum. Sources of Truth (MUST) covers paths, routes, messages and storage-state paths but not roles. Is a repeated role name a must or a should?
11. **Test Isolation is a SHOULD, `test-standards` says "must be independent".** `test-standards/SKILL.md` Critical keeps "Tests must be independent" and "Setup goes in `test.beforeEach()` or a fixture" after the link, because following the stronger sentence does not violate the row. Is independence a MUST in practice?
12. **`playwright.config.ts` is not under `config/`.** `data-strategy/SKILL.md` sends suite tuning (timeouts, retries) to `playwright.config.ts`; the No Magic Numbers row names `config/` or `enums/`. Should the row name the Playwright config too?
13. **A sixth selector tier.** `selectors/SKILL.md` allows CSS class or id selectors as a last resort after every semantic option; `selectors/references/locator-choice.md` says "a class-based locator does not ship". The row lists five tiers. Which is it?
14. **"Label" means two things.** The No Hardcoded Test Content row says "names, labels and text come from factories"; `data-strategy` says never Faker-generate an app-defined string (error message, label, heading, route). Compatible if the row means test-created content and the skill means app UI labels; worth one word in the row.
15. **Two ESLint rules have no Constitution row.** `no-focused-test` (`test.only`) and `explicit-function-return-type` enforce nothing in `AGENTS.md`; their comments point at Linting and the Workflow section. Should they get rows, or stay lint-only?
16. **Checklist tiers.** `pr-reviewer/references/constitution-checklist.md` assigns 🔴/🟠/🟡 per item with no stated mapping from MUST/SHOULD/WON'T; No Magic Numbers is 🟡 although it is a WON'T. Is the tier per item deliberate?
17. **Are teaching snippets bound by the Constitution?** `helpers/SKILL.md` requires JSDoc on every exported helper, and its CORRECT `formatDate` example has none. Several skills carry examples that a strict reading of their own Critical block rejects. Bound or exempt?
18. **Null-body responses.** The Response Validation row says "exactly `expect(SchemaName.parse(body)).toBeTruthy();`"; `api-testing/references/coverage-matrix.md` prescribes `expect(body).toBeNull()` for a 204, and `fixtures` uses a bare parse in fixture code. Both kept as skill-local carve-outs. Should the row mention them?
19. **Per-assertion timeouts and debug instrumentation.** `data-strategy` allows a per-assertion `{ timeout }` with a comment (No Magic Numbers says `config/` or `enums/`); `debugging/references/ci-replay.md` says to push temporary `console.log` instrumentation and remove it before merging, while `eslint.config.mts` sets `no-console: error`. Deliberate exceptions, or gaps in the rows?
20. **Two confidence scales.** `ai-native-workflow` gates proposals (below 5 stop, 5–7 accept unknowns, 8+ proceed) and `pr-reviewer` reports a review confidence with its own meaning. Both are called confidence. Rename one?
21. **ESLint-only rules.** `no-console`, `require-top-level-describe` and `expect-expect` are errors in `eslint.config.mts` and appear in no prose. Fine as lint-only, or do they want a home?
22. **Maintainer instructions in README.** README still tells readers to regenerate skills after edits and to verify, reinstall and re-lock vendored skills; CONTRIBUTING owns the same policy. Keep both, or point README at CONTRIBUTING?
23. **The `{area}` placeholder has no numbered home.** `AGENTS.md` introduces it in a sentence above the MUST list; the hard instruction ("resolve with `ls`, never guess") lives in `common-tasks` Critical. A row, or fine as is?
24. **Explicit return types, three scopes.** `type-safety` says every exported or public function; `eslint.config.mts` enables `explicit-function-return-type` for every function; README says something in between. One scope?
25. **Three skill-local requirements live only in references or procedures.** The API step-name shape (`<verb> <resource> via <METHOD> <path>`) is only in `api-testing/references/multi-call-steps.md`; the 204 null-body carve-out only in `api-testing/references/coverage-matrix.md`; the inline HTTP-status literal carve-out only in the `enums` Procedure table. Each is a rule with no Critical home. Promote them, or accept references as homes for area detail?

26. **The README's current-user example disagrees with the demo code.** `README.md` shows `GET /api/users/me` validated with the login-response schema; `enums/app/app.ts` and the demo API use `/users/me` with a separate profile response, and `fixtures/api/schemas/util/errorResponseSchema.ts` says the 401 body is undocumented while the current contract documents it. Found by four cold agents in a row while adding a test; pre-v2, not touched here.
27. **The hook's comments name scripts that do not exist.** `enforce_constitution.py` refers to `scripts/check-hook-eslint-parity.sh` and a hooks canary in five places; neither file is in v2.0.1. Pre-v2, not touched here.

## C. Tooling choices to confirm

28. **Anchors cost words.** `check-agents-md.sh` capped `AGENTS.md` at 800 words with 27 to spare; 36 anchors need 36. The cap is now 840 (815 used, 25 to spare). Anchors sit after the bold name so the row regex still finds the name.
29. **The manifest is gone.** `scripts/rules-manifest.txt` and the verbatim-token check are replaced by `check-rules-drift.sh` proving that 34 of the 36 rows are linked from at least one scaffold skill's Critical block (Type Safety and Test Steps are explicit, named exceptions that fail the gate once they gain an owner), that every Critical link to a row resolves, and that every rule id in `enforce_constitution.py` maps to a row. Ownership is now visible in the links rather than in a side file. The two tokens that were skill-local rules (`fuzz path parameters`, `find all consumers`) have nothing to cross-check.
30. **Prose paths are rejected.** `check-skill-references-drift.sh` fails on a rule-tree Markdown file (`AGENTS.md`, `CLAUDE.md`, a qualified `SKILL.md` path, `references/*.md`) named in prose, whether bare, backticked, or inside a backtick span with other text, instead of linked (`STRICT_PROSE_PATHS=1` by default). Exempt on purpose: the generic word `SKILL.md`, skill names ("the `api-testing` skill", "`api-testing` step 5"; `check-skill-crossrefs.sh` and `check-heading-pointers.sh` cover them), code paths, YAML frontmatter, the `@AGENTS.md` import line in `CLAUDE.md`, a pruned file that the initializer marks `CLAUDE.md (omitted)` (accepted only while the file is really absent), and vendored skills.
31. **The gates have a self-test.** `scripts/tests/run.sh` runs 35 fixture trees under `scripts/tests/fixtures/` (`npm run check:gates-selftest`, also in `skill-lint.yml`). No equivalent existed; it transfers even if nothing else does.
32. **`skill-lint.yml` says "pure bash + git".** The gates use bash plus python3 (as `check-heading-pointers.sh` and `check-skill-shape.sh` already did). Update the comment?
33. **The initializer commits without a git identity.** `packages/create-agentic-playwright/bin/create.js` runs `git commit` with no `user.name` fallback and logs failure as not fatal; on a bare runner the scaffold commit silently does not happen. Pre-v2 note, still true.
34. **Hook messages restate rules.** The 18 messages in `enforce_constitution.py` name their rule ("Constitution WON'T: No XPath") and some repeat its text; the no-xpath message listed the whole selector order and went stale when a tier was added in a trial. It now points at the row. Should every message point at the row instead of repeating it, given a hook message cannot be a link?
35. **Tried by cold agents before handing over.** Seven Codex runs with no knowledge of this branch: three contributor tasks on the branch (change the selector order; add a hook-enforced rule; add a "reminder" to a skill) and four codegen tasks on scaffolds from the branch and from v2.0.1. Changing a rule touched the row only; adding a rule needed the row, the hook tuple and one Critical link once the gate stopped hardcoding the row count and the hook map (it did at first, and the agent edited 37 fixture files); the reminder came back as a link followed by a restatement, which the gate cannot see, so CONTRIBUTING now says a link stands alone. The generated API specs were rule-for-rule the same on both scaffolds.
